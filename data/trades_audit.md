## 4. 可补全性

### 4.1 同一 (股票代码, 操作日期) 多记录配对

- 全表共有 **912** 个 (代码, 日期) 唯一组合
- 仅 **10 组** (21 行) 在同一天同一只股票有多条记录
- 其中 **4 组** 同时存在"纯买入行 + 纯卖出行",可通过行内配对补全卖出价/数量
- 可高置信补全: **卖出价 4 行, 卖出数量 4 行**

### 4.2 跨日补全 `前期买入价格`

- 缺失 620 行
- 通过 "**上一交易日同股票的当天卖出价格**" 可补: **174 行** (高置信)
- 其余 446 行要么是首次建仓(无前置卖出),要么对应股票此前未出现

### 4.3 综合分类

| 分类 | 估算可补全行数 | 补全策略 | 风险 |
|---|---|---|---|
| **高置信可补全** | **约 178 行** | 174 行 `前期买入价格` + 4 行 `当天卖出价格` + 4 行 `当天卖出数量` | 跨日补全用上一交易日卖出价,在"T+1 平仓"假设下准确;若有 T+0 反向操作会失真 |
| **可能可补全** | **约 30 行** | 22 行买卖齐全但缺 `当天盈利毛利`(可由价×量推算)+ 5-10 行其他部分列缺失行 | 毛利定义本身不清(包含费用?扣税?),需先与业务确认 |
| **不可补全** | **剩余约 740 行** | 大量纯买/纯卖无配对行 + 26 行完全空白行 + 100% 空 `当天毛利比例` | 源头缺失或缺少外部关联数据 |

## 5. 价格×数量 与 实际净盈利 的关系

### 5.1 直接验证 (同一天同时有买卖价)

只有 **32 行** "当日买卖齐全" 的样本,其中仅 **2 行** 还同时填了 `实际净盈利`:

| 日期 | 代码 | 买价 | 买量 | 卖价 | 卖量 | 实际净盈利 | 推算毛利 (卖-买)×卖量 | 差异 |
|---|---|---|---|---|---|---|---|---|
| 2026-03-18 | 2040 | 10.70 | 5000 | 11.00 | 2000 | 600 | 600 | **0** |
| 2026-04-15 | 603799 | 62.92 | 500 | 65.05 | 200 | 406 | 426 | -20 |

- **结论 A**: `实际净盈利 = (当天卖出价 - 当天买入价) × 当天卖出数量` 在部分样本成立,部分有差异(可能含手续费/印花税)。
- 样本太小(2 行),不能给出通用公式。

### 5.2 用 `前期买入价格` 作成本价 (95 行实际净盈利 + 卖出价/数量齐全)

| 公式 | 样本数 | 差异 < 1 元 | 差异 < 100 元 |
|---|---|---|---|
| `实际净盈利 = (卖出价 - 前期买入价) × 卖出数量` | 70 | 16 (22.9%) | 16 |
| `推算成本价 = 卖出价 - (实际净盈利 / 卖出数量)` | 72 | 30 (41.7%) vs `前期买入价` | — |

- 大量样本中 `实际净盈利` **远超** `(卖价-成本)×卖量` 的预期值,例如:
  - 601339 @ 2026-02-25: 卖 10000 股 @ 5.20,前期买入价 5.00 → 预期毛利 2000,实际净利 **8094** (4 倍)
  - 426 @ 2026-03-04: 卖 100 股 @ 51.62,前期买入价 47.90 → 预期毛利 372,实际净利 **6563** (17 倍)
- 一些样本中 `实际净盈利 ≈ (卖价-前期买入价) × 卖量` (差 <1 元),例如:
  - 2040 @ 2026-03-18: 卖 2000 @ 11.00,前期 10.70 → 600 ✓
  - 603799 @ 2026-04-16: 卖 500 @ 65.10,前期 62.92 → 1090 ✓

### 5.3 解读与结论

1. **`实际净盈利` 字段含义模糊**:部分情况下是"单笔毛估",部分情况下明显是**整轮持仓的累计净盈亏**(含此前多笔买入的差价、分红、扣税等)。
2. **不能用单一公式反推**:要么放弃自动推算 `实际净盈利`,要么先与业务/录入者确认该列的真实定义。
3. **单位净利率** (净利/卖量/卖价) 在 97 个有效样本中位数为 **9.31%**,可作为合理性校验的下限参考,但不能用作推算。

## 6. 总结与建议

### 6.1 数据质量概览

- **数据规模**: 950 行 / 204 只股票 / 6.5 个月,基础键(日期/名称/代码)完整率 97%+。
- **数据形态**: 表是 "**事件流**" 而非 "**当日盈亏汇总**",约 81% 的行只有买入或只有卖出——这是正常的交易日志结构,**不是数据缺失**。
- **价格×数量 同步**:无脏数据。
- **真正的"硬缺失"**: `当天毛利比例` 100% 缺失(源头就这样)。

### 6.2 建议的补全优先级

| 优先级 | 动作 | 预期收益 | 工作量 |
|---|---|---|---|
| P0 | 在 ETL 中加 "上日卖出价 → 前期买入价" 跨日回填 | **+174** 行 `前期买入价格` | 5 行 SQL |
| P0 | 在 ETL 中加 "同日同代码多记录配对补全卖出价/数量" | **+4** 行 `当天卖出价格` / `当天卖出数量` | 10 行 SQL |
| P1 | 与业务确认 `实际净盈利` 字段的真实定义;若是单笔毛利,补公式校验;若是持仓级,改列名/加注释 | 解决公式不确定性问题 | 1 次访谈 |
| P1 | 在 ETL 中按 `当天买卖齐全 + 数量齐全` 推算 `当天盈利毛利` | **+~22** 行 | 10 行 SQL |
| P2 | 与录入者确认 `当天毛利比例` 是否原本就应计算填入 | 决定是否可恢复 | 1 次访谈 |
| P3 | 26 行完全空白 + 1-1-1-1 的孤立列缺失 | < 5 行,边际收益低 | 人工核查 |

### 6.3 高置信可补全 / 可能可补全 / 不可补全 三档分类

| 档位 | 行数估算 | 占比 |
|---|---|---|
| **高置信可补全** | **~178** 行(174 前期买入价 + 4 卖出价/数量) | 18.7% |
| **可能可补全** | **~30** 行(22 毛利推算 + 5-10 其他) | 3.2% |
| **不可补全** | **~742** 行(大头:489 纯买入无卖出 + 231 纯卖出无买入 + 70 类似 + 100% 空 `当天毛利比例`) | 78.1% |

注: 不可补全的 ~742 行中,**绝大多数并非真"缺失"**,而是 "当天只做单边操作" 的合理状态——补全它们需要的不是 ETL,而是合并 T+N 交易的持仓视图(汇总为"持仓级 P&L")。

## 附录 A. 审计 SQL 模板(可重跑)

```sql
-- 1. 空值分布
SELECT
  SUM(CASE WHEN 操作日期 IS NULL THEN 1 ELSE 0 END) AS 日期空,
  SUM(CASE WHEN 股票代码 IS NULL THEN 1 ELSE 0 END) AS 代码空,
  SUM(CASE WHEN 前期买入价格 IS NULL THEN 1 ELSE 0 END) AS 前期价空,
  SUM(CASE WHEN 当天买入价格 IS NULL THEN 1 ELSE 0 END) AS 买价空,
  SUM(CASE WHEN 当天卖出价格 IS NULL THEN 1 ELSE 0 END) AS 卖价空,
  SUM(CASE WHEN 当天买入数量 IS NULL THEN 1 ELSE 0 END) AS 买量空,
  SUM(CASE WHEN 当天卖出数量 IS NULL THEN 1 ELSE 0 END) AS 卖量空,
  SUM(CASE WHEN 当天盈利毛利 IS NULL THEN 1 ELSE 0 END) AS 毛利空,
  SUM(CASE WHEN 实际净盈利  IS NULL THEN 1 ELSE 0 END) AS 净利空,
  SUM(CASE WHEN 当天毛利比例 IS NULL THEN 1 ELSE 0 END) AS 比例空
FROM trades;

-- 2. 纯买入 / 纯卖出行数
SELECT
  SUM(CASE WHEN 当天买入价格 IS NOT NULL AND 当天卖出价格 IS NULL THEN 1 ELSE 0 END) AS 纯买入,
  SUM(CASE WHEN 当天卖出价格 IS NOT NULL AND 当天买入价格 IS NULL THEN 1 ELSE 0 END) AS 纯卖出,
  SUM(CASE WHEN 当天买入价格 IS NOT NULL AND 当天卖出价格 IS NOT NULL THEN 1 ELSE 0 END) AS 买卖齐全
FROM trades;

-- 3. 同一 (代码,日期) 多记录
SELECT 股票代码, 操作日期, COUNT(*) AS 行数
FROM trades
GROUP BY 股票代码, 操作日期
HAVING COUNT(*) > 1;
```
